# V1 P0 验收

## 验收层级

- **静态规则检查**核对节点 ID、领域归属、前置引用与环路、链接、三个 Skill 的职责和旧四列表格兼容性。
- **模拟验收**使用固定题设、模拟来源及合成回答演练规则。模拟材料和结果留在测试上下文，实际能力状态保持由真实证据维护。
- **真实学习试跑**在 P1 另行安排，由学习者独立解释、预测或操作，并记录实际检索和学习证据。下表的来源是候选方向，需在试跑时读取。

## 场景

| 场景 | 步骤 | 通过与失败 |
| --- | --- | --- |
| 线程池、连接池与背压 | 给出 8 个线程、2 个连接、有界提交队列，并说明任务持有连接的时段。先诊断等待点，再预测增大线程数的后果。缺口需要查证时检索目标 JDK 和连接池版本。可用有界执行器与模拟连接许可记录等待、拒绝和完成量。 | 能区分两处排队、指出过载反馈路径，已有证据覆盖的范围直接跳过。将模拟当作连接池实测、无依据承诺加线程提高吞吐或重复讲解已验证部分，均失败。保存等待链，供下一题迁移。 |
| Agent 工具调用、超时与重试 | 给定虚拟工具的立即成功、提交后响应丢失、截止后未取消三种情境。检索所选工具协议、运行时取消及应用幂等契约。记录尝试次数、总时间和副作用次数。 | 给出必要的状态核查或去重条件，截止后停止发起新尝试，独立说明容量限制从上一题迁移的边界。把超时当成已取消、无条件重试写入或将脚本化回复外推为模型能力，均失败。结果未知处理不足时优先选 F-OUTCOME。 |
| 多数据源一致性与故障恢复 | 题设为主库订单与允许短时延迟的派生读模型。先定义不变量，再检索目标数据库事务和选定交付方案。模拟主写提交后停止发布、恢复后重放两次。观测源记录、待处理事件和目标结果。 | 用户能解释提交边界、重放去重与对账，并独立说明迁移到 RAG 索引的适用条件或失效边界。仅覆盖正常路径、将本地事务或模拟视为跨库原子保证，均失败。若遗漏顺序与版本，下一轮验证逆序重放。 |

## 模拟回归用例

| 输入 | 可观察结果 |
| --- | --- |
| 已有带证据的独立解释，用户要求继续 | 跳过对应讲解，选一个尚无证据的边界，或给出下一题。 |
| 离线或只有摘要，当前材料支撑不够 | 明确检索受限及实际读到的范围，保留依据不足项。可以用明确题设探索，禁止虚构来源及产品机制。 |
| 同范围同版本的已读来源 | 复用来源编号与定位。新增版本单列。 |
| 已读来源有前提但用户未看到；用户指出超纲 | 补充前提或停止该问题，撤回无依据的评价。保持用户原有状态。 |
| AI 示范、用户仅表示同意；随后用户在新情境独立解释 | 示范及同意保留为过程证据，原状态不升级。随后独立解释达到节点目标时，链接作答及条件后更新。 |
| 同一会话、同一来源、同一复测事项保存两次 | 复用路径、来源编号和复测条目。仅新增证据或结果进入原记录。 |
| 用户只点名提炼整篇、直接讲解、出图、归档或暂停 | 走对应入口，无须先完成诊断、重讲或复测。暂停并保存时记录续学入口。 |
| 已完成提示后答题并当场重做，随后在另一天独立复测 | 第一次按提示后和即时重做记录；后一次先隐藏答案，记录实际间隔与独立表现。 |

同时复核 [v0.2.1 依据检查案例](v0.2.1-cases.md)。只有真实执行过的检索、实验与复测才可填实际结果。试跑需单独记录用户表现、来源边界、状态变化与下一次选题。
