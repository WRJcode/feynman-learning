# v0.2.1：依据检查案例

以下是基于真实试跑问题编写的行为验收场景；不是自动化测试，也不表示新版已完成会话试跑。

| 场景 | 应有行为 | 不应发生 |
| --- | --- | --- |
| 已读概览只介绍 AgentSpec 是规范包，用户用紧箍解释规范生效 | 保留启发性关联，说明实际执行方式未展开 | 将佩戴、绑定对象、念咒逐项映射为真实实现 |
| AI 曾说“平台读取后执行”，但无来源，用户说不读取就无约束 | 将讨论限定为假设，或查证后再讲 | 因 AI 说过，就认定可继续按标准答案追问 |
| 用户说“没有指定约束哪个 Agent” | 视为机制假设，检查材料是否支持 | 先肯定这是正确步骤，再追问执行机制 |
| 用户指出“上一章没涉及” | 停止问题链，撤回无依据评价；不记用户失败或待重讲 | 以费曼重讲为由要求继续推演未知机制 |
| 来源明确介绍下载 Skill 包，且材料已经提供 | 可让用户用自己的话解释“获得方法包”和“调用远程入口”的已知差异 | 因为强调边界就完全不再验证 |
| 来源已读但提炼漏掉关键前提 | 补讲并标记提炼遗漏，然后按需重讲 | 将遗漏归因于用户没学会 |
| 用户主动要求猜想新机制 | 明确为探索，保留假设及待查证点 | 把推测写入事实性总结或掌握证据 |

## 本次试跑的纠偏

“未读取则无约束”的讨论可作为一般假设下的推演，不能直接证明特定产品行为。“绑定具体 Agent”和“按规范执行”此前由对话推导出，不能声称 Nacos 概览已给出实现流程。用户指出来源边界，是有效的学习判断，不是需要被纠正的理解不足。
