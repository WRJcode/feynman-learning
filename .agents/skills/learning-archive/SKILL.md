# 总结归档

用户要求归档即可执行本地写入；不要求完成验证流程。只根据可见对话、已读来源和真实实验记录工作。

1. 定位目标学习仓库和主题，读取已有 index.md、synthesis.md 及相关来源、会话。名称不明确且会影响写入时先澄清，不覆盖不确定的主题。
2. 保存尚未记录的重要用户解释、验证问题、作答、提示、实验及修正依据。保留原始表达；转述标为转述，未获认可的 AI 补充独立标记。
3. 有值得复用的当前理解时创建或更新 synthesis.md：当前解释、关键关系、适用边界、误解及修正、验证结果、未解决问题和复测题。每个关键结论链接来源 S 标识或会话证据。无法确定出处时写待补来源。
4. 更新 index.md 的目标、当前状态、证据、下一步。主题索引保留原有格式，记录主题内证据及范围。能力地图存在时按下文规则回写匹配节点。
5. 如需复测，更新 reviews/queue.md。用户指定日期时采用该日期；未指定写待安排，可以提出建议但不冒充用户选择。到期提醒依赖后续会话，没有后台调度。复测完成后更新原条目，保留结果，避免重复。
6. 回复实际文件路径、当前未解决问题和可选下一步，明确未运行的实验或未读取的材料。

归档抽象与跨领域关联时，保留用户提出的其他知识或事物、对应结构、成立依据和类比边界。将一轮验证产生的 Mermaid 理解图保存在会话中，当前总结按需引用或复用；没有用户关联就不编造。图上的待验证连接和 AI 补充须保留标记，不将类比当作事实或因果证据。图的修订记录与理解修订保持一致。

## 文件与重做

在指定的学习仓库写入，不写 Skill 安装目录。有 templates/ 时按需裁剪；无模板时采用上述字段，不强制生成空文件。新会话使用实际日期和未占用编号；恢复或重复归档根据已知路径、主题与会话证据定位原会话，更新原条目。只有新证据才追加，无法安全识别目标时先澄清。简单主题可合并为单个 Markdown 文件。

重做当前总结时，根据反馈修订；重要观点变化注明日期、变化及依据，历史会话保持可追溯。未初始化 Git 时不能声称 Git 已保存历史，必要时先保存修订前的独立副本。不要删除原始材料和无关内容。

归档不自动 commit 或 push，用户明确要求或已有约定时再执行。用户只要求在对话中总结时不写文件。没有足够过程记录也可归档，但清楚标记仅材料整理、理解待验证。

## 成果与能力地图

按价值保存实际产生的成果，允许本轮只有材料或进度。

- **认知**保留用户独立解释的原话或明确标记的转述及其证据位置；提示后过程和 AI 图示可另存为学习过程。
- **工程**记实际验证类型、版本、执行情况、结果和边界。未运行的设计标为方案，脚本化模型与真实组件分别标记。
- **迁移**链接用户独立作出的跨域判断或实践，保留共同结构、适用前提和失效边界。
- **职业**只用真实经历，记录本人职责、约束、取舍和可核对结果，优先复用脱敏案例链接。信息待核对时保留为线索。

先保存或定位证据，再更新 KNOWLEDGE-MAP.md 中匹配的能力节点。同一文件内保留当前状态、证据链接、作答条件与下一步，详细过程留在原会话。工作案例只有在用户职责、决策或操作及结果足以支持节点目标时才用于更新。独立解释可支持能解释，独立新情境判断、得到验证的工程表现或有据工作案例可支持能应用，间隔后独立复测可支持复测通过。有实际接触记录可记已接触；没有接触或诊断证据保留未诊断。提示后表现按条件记录，用户仅认可、AI 示范、AI 独立运行实验均不触发掌握升级。证据撤回时按剩余证据修订。无地图时只走原有主题归档流程，按同一证据标准更新主题索引，证据不足时记待验证。

同一会话复用会话路径，同版本和范围的来源复用 S 编号，同一复测事项更新原条目。保存完成后按当前目标、关键前置、到期复测和可用的迁移机会推荐一个下一步。用户只要求保存进度时，记录阶段与续学入口即可。

## 费曼闭环归档

优先呈现“用户初次解释 → 已确认缺口 → 补学依据 → 用户重讲 → 变化与未决点”，而非只保存 AI 润色后的答案。缺少任一环节如实写未进行；用户确认或请求画图不能充当重讲。标明重讲是独立完成、提示后完成还是看过 AI 示范后完成。没有重讲仍可归档；仅在有据补学或真实表达缺口后尚待重讲时记待重讲。材料不足或问题越界单独记录，不阻止结束。图与总结中的成熟关系若主要由 AI 提供，不提高用户掌握状态。保留旧会话，不用新规则追溯改写过去的证据。

## 来源不足与越界问题的归档

记录关键纠正的具体依据以及提问前提是否曾提供。AI 没有依据的肯定、纠正和机制映射要明确撤回或降级为假设，不纳入事实性总结；不得仅因用户接受就升级为可靠结论。记录“材料不足”“AI 越界”“用户表达缺口”之间的区别。被撤回的问题不再列为用户待重讲或失败，不降低既有状态，仍保留用户合理抽象与关联。待查证问题与待重讲任务分开。
